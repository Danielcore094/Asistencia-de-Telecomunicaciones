COMANDOS DE DESPLIEGUE DOCKER - MODO HIBRIDO
==============================================

Este archivo corresponde exclusivamente a:
    docker-compose.servidor-hibrido.yml

El modo hibrido utiliza servicios externos:
- Base de datos PostgreSQL en Supabase.
- Redis distribuido en Upstash.
- Evolution API externa.

No crea PostgreSQL local y no debe ejecutarse con "docker compose up" sin
indicar el archivo docker-compose.servidor-hibrido.yml.


1. REQUISITOS
-------------

- Docker Desktop en Windows, o Docker Engine y Docker Compose en Linux.
- El archivo docker-compose.servidor-hibrido.yml.
- Un archivo .env con las variables de produccion.
- Las imagenes telecom-backend y telecom-frontend con la misma etiqueta
  indicada por IMAGE_TAG en .env.

Variables obligatorias del .env:
    DATABASE_URL
    DIRECT_URL
    JWT_SECRET
    CORS_ALLOWED_ORIGINS
    FRONTEND_URL
    UPSTASH_REDIS_REST_URL
    UPSTASH_REDIS_REST_TOKEN
    TURNSTILE_SECRET_KEY
    VITE_TURNSTILE_SITE_KEY
    EVOLUTION_API_URL

Nunca compartir el archivo .env porque contiene credenciales y secretos.


2. UBICARSE EN LA CARPETA DEL PROYECTO
---------------------------------------

Windows PowerShell:
    Set-Location "C:\ruta\al\proyecto"

Linux Bash:
    cd /ruta/al/proyecto


3. CARGAR LAS IMAGENES DESDE UN ARCHIVO TAR
--------------------------------------------

Ejecutar si las imagenes fueron transportadas en un archivo .tar:

Windows PowerShell o Linux Bash:
    docker load --input asistencia-imagenes-2026-09-14.tar

Comprobar las imagenes cargadas:

Windows PowerShell:
    docker image ls telecom-backend
    docker image ls telecom-frontend

Linux Bash:
    docker image ls telecom-backend
    docker image ls telecom-frontend

La etiqueta de las imagenes debe coincidir con IMAGE_TAG del archivo .env.


4. VALIDAR LA CONFIGURACION
----------------------------

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml config

Si el comando termina sin errores, las variables obligatorias estan completas.


5. INICIAR EL DESPLIEGUE
-------------------------

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml up -d

Este comando inicia solamente los contenedores backend y frontend.
No crea otra base de datos ni otra instancia de Evolution API.


6. COMPROBAR EL ESTADO
-----------------------

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml ps

Windows PowerShell:
    Invoke-WebRequest http://localhost:3000/api/salud -UseBasicParsing

Linux Bash:
    curl http://localhost:3000/api/salud

Respuesta esperada:
    {"estado":"disponible"}

Abrir la aplicacion en:
    http://localhost:3000

Desde otro equipo de la red, usar la IP del equipo donde corre Docker:
    http://IP_DEL_EQUIPO:3000


7. CONSULTAR LOGS
------------------

Ver los ultimos logs del backend:

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml logs --tail=100 backend

Ver los ultimos logs del frontend:

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml logs --tail=100 frontend

Seguir los logs del backend en tiempo real:

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml logs -f backend

Ver todos los servicios:

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml logs --tail=200


8. ACTUALIZAR LA APLICACION
----------------------------

1. Cambiar IMAGE_TAG en .env a la etiqueta de la nueva version.
2. Cargar el nuevo archivo .tar si las imagenes fueron transportadas.
3. Validar la configuracion.
4. Levantar nuevamente los contenedores.

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml config
    docker compose -f docker-compose.servidor-hibrido.yml up -d
    docker compose -f docker-compose.servidor-hibrido.yml ps

Si se desea reconstruir el frontend desde el codigo local:

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml build frontend
    docker compose -f docker-compose.servidor-hibrido.yml up -d

El backend del Compose hibrido utiliza una imagen ya construida. Para cambiar
el backend, primero cargar una nueva imagen con la etiqueta indicada en IMAGE_TAG.


9. DETENER Y REINICIAR
-----------------------

Detener los contenedores sin afectar Supabase, Upstash ni Evolution API:

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml down

Iniciar nuevamente:

Windows PowerShell o Linux Bash:
    docker compose -f docker-compose.servidor-hibrido.yml up -d

No es necesario ni recomendable usar "down -v" en este modo.


10. DIAGNOSTICO DE ERRORES
---------------------------

Error: POSTGRES_USER, POSTGRES_PASSWORD o POSTGRES_DB faltante.

Causa: se ejecuto el Compose local por error.
Solucion:
    docker compose -f docker-compose.servidor-hibrido.yml config

Error: container name is already in use.

Consultar los contenedores existentes:
    docker ps -a --filter name=telecom_backend --filter name=telecom_frontend

Detener el proyecto hibrido y volver a iniciarlo:
    docker compose -f docker-compose.servidor-hibrido.yml down
    docker compose -f docker-compose.servidor-hibrido.yml up -d

Error Prisma P1001 o "Can't reach database server".

Windows PowerShell:
    Test-NetConnection HOST_DE_SUPABASE -Port 5432

Linux Bash:
    nc -vz HOST_DE_SUPABASE 5432

Tambien comprobar que DATABASE_URL y DIRECT_URL apunten a la base correcta y
que Docker tenga acceso a Internet.

Error 500 en la aplicacion:

    docker compose -f docker-compose.servidor-hibrido.yml logs --tail=200 backend
    curl http://localhost:3000/api/salud

Un endpoint que exige autenticacion puede devolver 401 sin que sea un error
 del servidor. Primero comprobar /api/salud y luego iniciar sesion.


11. PREPARAR IMAGENES PARA OTRO EQUIPO
---------------------------------------

Ejecutar en un equipo con acceso a Internet y Docker.

Windows PowerShell:
    $env:IMAGE_TAG = "2026-09-20"
    docker compose -f docker-compose.servidor-hibrido.yml build frontend
    docker save -o asistencia-imagenes-hibrido.tar `
      telecom-backend:$env:IMAGE_TAG `
      telecom-frontend:$env:IMAGE_TAG

Linux Bash:
    export IMAGE_TAG=2026-09-20
    docker compose -f docker-compose.servidor-hibrido.yml build frontend
    docker save -o asistencia-imagenes-hibrido.tar \
      telecom-backend:$IMAGE_TAG \
      telecom-frontend:$IMAGE_TAG

Copiar al equipo de destino:
- asistencia-imagenes-hibrido.tar
- docker-compose.servidor-hibrido.yml
- .env

En el equipo de destino:
    docker load --input asistencia-imagenes-hibrido.tar
    docker compose -f docker-compose.servidor-hibrido.yml config
    docker compose -f docker-compose.servidor-hibrido.yml up -d
    docker compose -f docker-compose.servidor-hibrido.yml ps
